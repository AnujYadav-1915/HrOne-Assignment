# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 36-37) | Checked `minutes > 10` after integer floor division `minutes = int(diff / 60)`. For 09:40:01 on a 09:30 shift (601 seconds), `minutes` is 10, so `10 > 10` evaluates to False, returning 0 instead of 10. | Tested punch-in at 09:40:01. Rule R2 requires 10 late minutes, but the starter returned 0. | Checked `diff_seconds > 600` before dividing to properly apply the 10-minute grace period. |
| 2 | `compute_late_minutes` (lines 34-35) | Used `punch_in.replace(hour=h, minute=m)` directly on the punch time without timezone handling. For overnight shifts where punch-in happens past midnight, this compared against the current calendar day instead of the previous day's shift start. | Tested overnight shift (22:00 - 06:00) punching in at 00:05. Returned 0 late minutes instead of 125. | Built the shift start datetime in IST using the record's attendance date. |
| 3 | `compute_work_hours` (line 41) | Used Python's built-in `round()`, which does banker's rounding on floats (round-half-to-even) instead of round-half-up, and didn't truncate instants to whole seconds. | Tested 2.555 hours, which rounded down to 2.55 instead of 2.56. | Truncated instants to whole seconds and used Python's `Decimal` with `ROUND_HALF_UP` to 2 decimal places. |
| 4 | `compute_overtime` (line 47) | Computed overtime without checking the minimum 30-minute threshold required by rule R3. | Tested punch-out at 18:35 for an 18:30 shift end (5 minutes late). Starter returned 5 instead of 0. | Added a check to only return overtime when `diff_seconds >= 1800` (30 minutes), otherwise returning 0. |
| 5 | `compute_overtime` (lines 45-46) | Built shift end on `date_str` without adding a day for overnight shifts (`shift_end <= shift_start`), and mixed offset-naive and offset-aware datetimes. | Tested overnight shift punch-out. Raised `TypeError: can't compare offset-naive and offset-aware datetimes`. | Added 1 day to `date_str` for overnight shifts and ensured both datetimes are timezone-aware in IST. |
| 6 | `health` (lines 72-74) | Returned `{"status": "ok"}` directly without checking if MongoDB is reachable. | Stopped MongoDB; the `/health` endpoint still returned 200 instead of 503. | Added `client.admin.command("ping")` inside a try-except block, raising a 503 HTTPException if the database is down. |
| 7 | `create_employee` (lines 78-85) | Used check-then-insert (`find_one`) with no unique index on `emp_code`, and didn't validate that `shift_start` must differ from `shift_end`. | Sending two duplicate requests concurrently caused duplicates or 500s. Equal shifts returned 201 instead of 422. | Added a unique index on `emp_code`, caught `DuplicateKeyError` to return 409, and added Pydantic validation for shifts. |
| 8 | `create_employee` (line 82) | Set `created_at = datetime.now()`, which FastAPI serialized as an ISO string instead of epoch milliseconds integer. | Looked at response payload; `created_at` was a string instead of an int. | Stored UTC datetime in MongoDB and converted it to integer epoch milliseconds in the API response. |
| 9 | `list_employees` (line 93) | Calculated pagination skip as `page * page_size`, meaning page 1 skipped the first 20 employees. | `GET /employees?page=1` did not return the first page of results. | Changed calculation to `(page - 1) * page_size`. |
| 10 | `list_employees` (lines 94-95) | Counted the entire collection with `count_documents({})` ignoring the department filter, and did not sort by `emp_code`. | Filtered by department, but `total` still showed all employees in the database, and order was inconsistent. | Passed the query filter `q` to `count_documents(q)` and added `.sort("emp_code", 1)`. |
| 11 | `punch_in` (lines 100-121) | Relied on `find_one` before inserting (race condition), crashed with 500 if employee did not exist, didn't handle overnight shifts for attendance date, and added an extra `id` field. | Concurrent punch-ins caused 500 errors; punching in for a missing employee gave a 500 instead of 404; overnight punch-ins had the wrong date. | Returned 404 for missing employees, computed overnight dates, used unique index on `(emp_code, date)` for 409s, and removed `id` from response. |
| 12 | `list_attendance` (lines 144-150) | Loaded all matching records into memory with `list()` and sorted in Python, which would crash on 100k documents. Also missed secondary sort by `emp_code`, didn't validate `date_from > date_to`, and added an extra `id`. | High memory usage on large collections; passing `date_from > date_to` returned 200 instead of 422; response included an invalid `id` field. | Moved sort and pagination into MongoDB with compound index `[("date", -1), ("emp_code", 1)]`, added 422 check for dates, and formatted response correctly. |

## Things examined and decided NOT to be defects

1. **`python-dotenv` usage**:
   The starter loads `.env` with `load_dotenv()`. While the problem statement specifies that real environment variables must take priority, standard `load_dotenv()` does not overwrite existing system variables. It only provides default fallback values for local testing, which is standard practice.

2. **No user authentication**:
   The API has no authentication headers or login endpoints. The problem statement explicitly confirms that authentication is omitted for this assignment and `history.by` is plain text.
